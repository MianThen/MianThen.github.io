上一篇文章聊了回测引擎为什么要用定点数。这篇聊引擎上游的那个「大脑」：一个跑在 A 股截面上的时序 Transformer 选股模型。

这不是一篇「我的模型年化多少」的炫耀贴。恰恰相反，这篇文章里最有价值的部分，是一串精心设计的挑战者——ListMLE、LambdaLoss、Kendall 动态权重、PCGrad、GradNorm、三种对抗训练、对比预训练——**全部被预注册的实验门禁挡在门外**的过程。最终活下来的，是最朴素的那个基线。如果你只对「什么有效」感兴趣，这篇文章可能会让你失望；如果你对「怎么证明自己没被骗」感兴趣，希望这些记录有用。

模型代码在 `python/qbt_ml/`（Python 研究层），推理制品最终落到 C++ 回测引擎里跑。全文所有数字都来自冻结的实验报告，不是事后回忆；涉及公开知识（文献、市场规则）的地方我会明确标注，和实验事实分开。

## 零、任务定义：这不是股价预测

先把问题钉死。很多「Transformer 预测股价」的项目死在这一步——问题定义本身就不成立。

我的任务是**截面排序**：每个交易日收盘后，给股票池里约 120 只股票打分，选 Top-20 持有，下一个交易日开盘成交（`NEXT_OPEN` 对齐）。模型不需要预测「明天涨多少」，只需要回答「开盘后第 5 根 K 线收盘时，哪 20 只的相对排名更靠前」。

这个定义直接决定了后面所有的设计：

- 每个训练 batch 是**一个完整 timestamp 的截面**（同一时刻的所有股票），而不是随机打散的样本——因为排序损失是截面内的相对比较；
- 标签从「下一根开盘买入、持有 5 根 K 线后卖出」的可成交路径构造，**成交时点被显式建模进标签里**，不存在「用收盘价预测收盘价」的偷价；
- 主指标是 NDCG@20、RankIC、top-bottom 收益差和换手率——没有一个指标是「预测精度」。

**为什么是序列模型，而不是 LightGBM？** 业界截面选股的绝对主力其实是梯度提升树 + 人工因子库：训练快、可解释、对表格数据近乎免费的 SOTA。我选序列模型有三个动机：一是手工因子本质是人工归纳的时序模式，注意力机制理论上能自己学到数据驱动的模式；二是同一套表示可以服务多个下游头（收益、波动、方向、区间），树模型每个目标要单独训一棵；三是研究兴趣本身——我想把「端到端表示学习在 A 股截面上到底行不行」这个问题钉死。结论先说：能跑通，但赢得极其艰难。这正是本文要讲的故事。

**A 股微观结构的三条硬约束也必须写进任务定义**（公开市场规则）：T+1，今天买明天才能卖；涨跌停，主板 ±10%、创业板/科创板 ±20%、ST ±5%，封板时根本无法成交；停牌，长停牌会让标签窗口直接断裂。这就是为什么标签必须是「下一根开盘可成交」的口径，特征里必须带 `is_suspended` / `is_tradable` 这类状态位——不是工程洁癖，是这些约束直接决定收益能不能兑现。

## 一、模型架构：一个刻意做小的因果 Transformer

`TemporalTransformerV1`（`python/qbt_ml/models/temporal_transformer.py`）的全部超参：

```python
@dataclass(frozen=True)
class TemporalTransformerConfig:
    feature_count: int          # 23 个特征
    lookback: int = 64          # 回看 64 根 K 线
    d_model: int = 64
    nhead: int = 4
    num_layers: int = 3
    dim_feedforward: int = 128
    dropout: float = 0.1
```

d_model=64、4 头、3 层，放在今天属于「袖珍模型」。粗算一下参数量：每层 encoder 约 3.3 万（MHA 约 1.7 万 + FFN 约 1.7 万 + LayerNorm），三层加输入投影和六个预测头，总量十万量级。作为参照，数据侧是 119 只股票、1587 个交易日的约 18 万根 K 线明细——**样本十数万、参数十万**，这个容量是刻意压出来的。金融时序的信噪比低得离谱，容量每大一点，模型记住噪声的能力就强一点。另外这个模型最终要导出 ONNX 塞进 C++ 引擎做推理，小模型的延迟和内存开销都可控。

为什么用因果 encoder 而不是 decoder-only 架构？因为任务是「读懂一段历史、输出一个截面表示」，本质是编码而非生成；decoder-only 的自回归头对这个任务是多余的算力开销。因果掩码的作用只有一个：保证 t 时刻的表示里绝无 t 之后的信息。

### 因果掩码与填充掩码

输入是 `[batch, 64, 23]` 的窗口，两个掩码叠加：

```python
# 因果掩码：t 时刻只能用 t 及之前的信息
causal_mask = torch.triu(torch.full((T, T), float('-inf')), diagonal=1)

# 填充掩码：padding 位置不参与注意力
src_key_padding_mask = input.isnan().any(dim=-1)  # 实际更严格
```

值得说一句 padding：样本池里的股票上市时间不同，前几根 K 线往往是缺失的。我用**前向填充 + 尾端对齐**构造窗口，缺失部分用 mask 挡住，不参与注意力计算。这里有个容易踩的坑：如果只对「缺失值」做填充而不加掩码，模型会把「填充出来的 0」当成真实观测学进去——数据审计里专门有一条 PIT（point-in-time）校验防这个，181,273 行明细跑下来 PIT 违规为 0。

### 最后一个有效位置池化

Transformer 编码器输出 `[batch, 64, 64]`，怎么聚合成一个向量？最直接的做法是取序列最后一个位置——但 padding 股票的最后几根是无效的。实现里先算出每只股票最后一个有效位置，只取那个位置的 hidden state 作为序列表示：

```python
# last_valid_idx: [batch]
last_hidden = out[torch.arange(batch), last_valid_idx]
```

这个池化同时承担了「对齐到当前时刻」的作用：模型永远只输出「以最后一根有效 K 线为当前时刻」的截面表示，不存在未来信息泄漏。

### 六个头

序列表示之后接六个平行的预测头：

| 头 | 输出 | 作用 |
| --- | --- | --- |
| expected_return | 连续值 | 主排序分数 |
| expected_volatility | 连续值 | 风险估计 |
| direction_probability | (0,1) | 上涨概率 |
| lower_quantile / upper_quantile | 连续值 | 区间估计（用 `torch.sort` 保证单调） |
| confidence | (0,1) | 排序置信度，用于交易闸门 |

六个头共享 encoder，但梯度通过多任务权重组合回传。后文会看到，**怎么组合这六个头的梯度，本身就是一整轮消融实验**。

### 可解释性：注意力权重能看，但别全信

pipeline 里留了可解释性分析模块（`analysis/attention.py`）：注意力权重统计，看模型主要盯回看窗口的哪一段；Integrated Gradients，看哪个输入特征对输出贡献大。通用观察是注意力倾向于近期 K 线和量价异常的位置——符合直觉，但必须引用 Jain & Wallace（NAACL 2019）《Attention is not Explanation》的警告：注意力权重和特征重要性不是一回事，高注意力不等于因果贡献。所以我把 IG 当作交叉验证手段，两套工具结论一致时才采信，单看注意力热图就下结论的做法我不接受。

### Scaler 以 buffer 形式注册进模型

特征标准化（z-score）的 mean / scale 不是训练脚本里的全局变量，而是 `register_buffer` 进模型，随模型一起导出：

```python
self.register_buffer("scaler_mean", ...)
self.register_buffer("scaler_scale", ...)
self.register_buffer("input_protected", ...)
```

其中 `input_protected` 是 4 个布尔特征（停牌、上市、ST、可交易）的标记，这 4 个特征**跳过 z-score**，直接以 0/1 进网络。这个细节在后文「制品契约」里会再出现——标准化参数进 buffer，是从根上杜绝「训练和推理标准化不一致」的一步。

## 二、特征：BAR_V1 的 23 维

特征构建器叫 `BAR_V1`（`python/qbt_ml/features/bar_v1.py`），全部从 OHLCV + 复权因子 + 基础属性计算，一共 23 维：

**动量/收益类（6 个）**：过去 1/5/10/20 根 K 线的对数收益。用对数收益而不是百分比收益，是因为对数收益在时间上可加（多日收益 = 单日收益之和），统计性质干净得多。

**波动类（4 个）**：过去 5/10/20/60 根 K 线的收益波动率。

**量价类（4 个）**：成交量的滚动 z-score（`_rolling_zscore`）、价格相对均线的偏离（`ma_deviation`）、价格在近期区间的相对位置（`price_position`，0-1 区间内的值）、区间突破指标（`breakout`）。

**横截面类（1 个）**：当日收益的横截面排名（`cross_section_return_rank`）。这一维直接编码了「今天谁涨得比别人多」的截面信息——截面排序任务里，相对信息往往比绝对信息更有预测力。

**状态类（8 个）**：停牌标志、上市标志、ST 标志、可交易标志，以及它们的若干组合——其中 4 个是需要标准化豁免的布尔位。

关键设计：**信号价格 = 原始价格 × 复权因子**（`signal_price = raw_price * adjustment_factor`）。所有收益计算都用复权价格，避免分红除权造成虚假的收益尖刺——一根 -10% 的除权「假阴线」如果进模型，动量特征会被直接打歪。特征有效性由 `valid_mask`（finite ∧ 已上市 ∧ 未停牌）保证，无效样本不进入标签构造。

再补一句标准化的动机：截面 z-score 不只是为了数值稳定，它同时把「市场整体量纲漂移」从特征里抹掉——2021 年的成交量绝对值和 2023 年没有可比性，但「比同期均值高几个标准差」是可比的。这是金融特征工程和 CV/NLP 的一个本质区别：**金融特征的平稳性几乎全靠预处理造出来**。

## 三、标签：把「可成交」写进监督信号

`LabelSpecV2`（`python/qbt_ml/labels/spec_v2.py`）管标签。六个头对应六类标签，最值得展开的是排序类标签。

**收益标签**：下一根开盘买入、持有 5 根 K 线后的复权收益（`return_raw`）。训练对齐是 `NEXT_OPEN`，成交时点被显式建模——模型学的是「开盘买入持有 5 根」的真实可成交收益，不是收盘对收盘的幻觉。

**方向标签**：`sigmoid((r - 0) / 0.0025)` 的软标签。这里的 0.0025 是个「置信带宽」：收益 +0.25% 时输出约 0.73，±1% 时约 0.98/0.02。带宽太窄会退化成硬标签、被噪声主导；太宽则标签没有信息量。0.25% 大致是普通股票的日收益噪声量级边缘，是「让梯度平滑」和「保留方向信息」之间的折中——说实话，这个超参我没做过系统的敏感性分析，记录在案。

**排序标签**：核心是 `rank_utility`。原始收益先做 1%/99% 的 winsorize（缩尾）再转成 [0,1] 的 relevance 分数，作为排序损失的监督目标。winsorize 这一步很关键：A 股日收益长尾极重，不缩尾的话 outlier 会主宰排序损失的梯度。

为什么 relevance 要归一到 [0,1]？因为 NDCG 的 DCG 项形如 Σ (2^relᵢ − 1) / log2(i+1)，relevance 的尺度直接决定梯度分布。归一之后，不同截面的 DCG 才可比——A 股有的日子全市场大涨、有的日子普跌，不归一的话，损失会被「市场整体涨跌幅」这个与选股无关的因子主导。

所有标签的计算代码、参数、版本都被 SHA-256 进 manifest（见第十一节），标签口径变更会直接改变制品哈希——这是可复现性的最后一道锁。

## 四、训练协议：Purged Walk-Forward

样本是时序的，就不能随便切 train/val/test。我用的是带 purging 和 embargo 的 walk-forward：

```
train: 504 根  →  purge: 6 根  →  val: 126 根  →  purge: 6 根 + embargo: 5 根  →  test: 126 根
```

每个 fold 往前滚。这套切法的出处是 López de Prado《Advances in Financial Machine Learning》（2018）里的 Purged K-Fold：purge 是因为相邻 K 线的标签窗口重叠（持有 5 根意味着 t 和 t+4 的标签共享收益），不 purge 就会把测试信息漏进训练集；embargo 是再留 5 根安全边际，对付那些没被标签窗口覆盖、但信息仍在缓慢衰减的泄漏路径。金融 ML 里最常见的自欺就是随机 shuffle 后切分——泄漏藏得深、回测美如画、实盘现原形。

评估指标全部**按 timestamp 等权**聚合（`timestamp_walk_forward_splits` + `ranking_oos_metrics`）。之所以强调按 timestamp 等权，是因为截面样本数不均（审计显示每天 106–112 只），按样本加权会被大截面日期带偏。

顺带把指标定义钉死，后文要用：

- **RankIC**：每日截面「模型分数 vs 未来收益」的 Spearman 秩相关，再按日取均值；t 值衡量这个均值是否显著异于 0，业界惯例 |t|>2 算有点东西、>5 算强信号；
- **NDCG@k**：只看前 k 名的排序质量，和「买 Top-20」的交易动作直接对应；
- **spread**：分数最高组与最低组的未来收益差；
- **turnover**：相邻两期 Top-20 持仓的换仓比例，直接决定成本，后文会看到它有多重要。

## 五、排序损失消融：基线赢了，而且赢得很干净

这是全项目最「反直觉」的一轮实验（`docs/phase1b_experiment_report.md`）。先交代三个候选损失的理论出身：

- **legacy**：`-Pearson(score, relevance)`，把打分与 relevance 的截面相关系数取负当损失。它不直接优化任何排序指标，是一个全局平滑的代理目标；
- **ListMLE**：把排序建模成 Plackett-Luce 选择过程，最大化「按真实顺序逐个抽出整个排列」的似然；
- **LambdaLoss**：源自 LambdaRank（Burges 等人在微软的系列工作，2006–2010），对每个逆序对按交换后的 ΔNDCG 加权——工业界 Learning-to-Rank 的标配。

预注册假设是 ListMLE 或 LambdaLoss 至少在某几个指标上超过 legacy。结果（OOS，fold 聚合）：

| 损失 | NDCG@20 | RankIC | spread | turnover |
| --- | --- | --- | --- | --- |
| legacy | **0.6397** | **0.0548** | **+0.00284** | 0.1176 |
| ListMLE | 0.6309 | 0.0412 | +0.00179 | **0.1087** |
| LambdaLoss | 0.6131 | -0.0224 | -0.00216 | 0.1205 |

legacy 全面胜出；LambdaLoss 的 RankIC 直接转负。

事后分析，输的原因可能在样本几何：我的截面每天只有约 110 只票，PL 模型的排列空间是 110! 量级，每条样本只能提供一条「链」的似然信号，信号极稀疏；而 Pearson 用的是截面内全部两两配对的均值信息，约 6000 对。小截面 + 长尾标签 + 小模型，**梯度信号的方差成了主导因素，而理论上更优雅的排序损失恰恰是高方差的那批**。这个解释不一定是唯一真相——也许是温度系数、采样方式、标签 winsorize 的交互问题——但它和观察一致。postmortem 写了整整一页，但按预注册纪律，本轮 ListMLE 和 LambdaLoss 就是输了。

## 六、不确定性加权：Kendall 权重的一次惨烈翻车

多任务损失权重是另一个经典的坑。方法出处是 Kendall, Gal & Cipolla（CVPR 2018）的同方差不确定性加权：假设任务 k 的噪声服从零均值高斯、方差 σₖ² 可学，则多任务极大似然自然导出损失权重 1/(2σₖ²)。实现上为了数值稳定，学的是对数方差 `s_k = log σ_k²`，权重 = exp(−s_k)。

翻车点在于**这个参数化本身就是陷阱**：s_k 无界，优化器一旦发现「压低某任务的噪声估计」能单调降低总损失，就会一路狂奔。我的波动率任务残差比收益任务小两个数量级，它的 s_k 一路滑到 clamp 下限 -6，权重变成 exp(6) ≈ 403。也就是说，模型把 99% 的梯度预算花在了波动率头上，收益排序的监督基本被饿死。

OOS 对比（legacy + Kendall vs legacy 固定权重）：

| 配置 | NDCG@20 | RankIC | spread |
| --- | --- | --- | --- |
| legacy（固定权重） | 0.6397 | 0.0548 | +0.00284 |
| legacy + Kendall | 0.6384 | 0.0368 | +0.00134 |

NDCG 只掉了 0.21%，看起来「还好」；但 RankIC 掉了 32.9%，spread 掉了 52.8%。NDCG 是门禁的头指标所以 gate 拦住了，但这件事的教训是：**只看头指标会漏掉风险维度的退化**。

还有一个业界里不太政治正确的观察：多任务权重最稳的做法，往往还是最土的那个——网格搜索 + 固定权重。自动加权省的是调参时间，赌的是优化风景的形状。这次我赌输了，rank 任务的权重此后固定为 0.1。

## 七、梯度手术：PCGrad 与 GradNorm

六头共享 encoder，梯度打架是真实存在的。这个方向有一串文献：GradNorm（Chen et al., ICML 2018）按各任务梯度范数与相对训练速率动态调权；PCGrad（Yu et al., NeurIPS 2020）发现多任务梯度之间存在「冲突角」，做法是把每对梯度中互相抵消的分量投影剔除；后续还有 IMTL、Nash-MTL（把多任务当博弈谈判问题）等一串工作。理论上它们都在解同一个问题：共享表示上，不同任务的梯度互相踩踏。

两组都试了。结果：RankIC 提升（+0.0070 / +0.0071），但 NDCG、Precision、换手率全部退化（完整表格见 `docs/phase1e_experiment_report.md`）。PCGrad 的投影频率约 0.55——超过一半的梯度对存在冲突，机制上确实在干活，但**把冲突强行剔除之后，模型反而失去了用冲突梯度学到的某种平衡**。Gate 全部未通过。

这一轮最诚实的注释是：我**没有**把「RankIC 提升」写成「PCGrad 有效」。RankIC 提升但组合层面全面退化，说明 RankIC 单指标可能被梯度手术带偏了。预注册门禁拦下的不是「有效」的假象，而是「局部指标有效」的假象——这是写论文时最容易顺手犯的错，也是做交易时最贵的一种自欺。

## 八、对抗训练：三道门全关

最后的大招组合拳，全部以「鲁棒性」之名。三个方法各自的出身：FGM 的思想源自 Miyato et al.（2017）的虚拟对抗训练，对隐层加对抗扰动（`r = ε·g/‖g‖₂`）；PGD（Madry et al., ICLR 2018）是多步投影梯度攻击，我把扰动约束在特征空间并尊重 valid_mask——停牌股票的特征不能被扰动，这是 mask-aware 的含义；direction_apl 来自 APL（Ma et al., ICML 2020 的 Normalized Loss Functions），用 NCE+RCE 的对称损失组合专治标签噪声。

预注册门禁要求：对抗训练后**干净样本的 OOS 指标不得退化超过阈值**，且对抗样本上的鲁棒性确实提升。结果（`phase2b_oos_report.json`）：

- `clean_non_degraded = false`：干净 OOS 上 return_mae 退化 +0.0707，超过容许窗口；
- 所有变体（none / direction_apl / latent_fgm / feature_pgd）在全部噪音率（0.05/0.1/0.2）下均未通过 gate。

也就是说，三种对抗训练都没有在「不牺牲干净性能」的前提下通过验证。direction_apl 属于那种「理论上你一定想试」的方法——它最终把方向头的鲁棒性提上去了，但代价是主收益头退化。

这里有一条普适教训：Tsipras et al.（ICLR 2019）《Robustness May Be at Odds with Accuracy》论证过鲁棒性与干净精度之间存在结构性张力。在 ImageNet 上，这张力是「掉一两个点精度换鲁棒性」，可以接受；在信噪比极低的金融标签上，它变成了「把本就不多的信号也让渡出去」。更深一层的反省是：对抗训练保护的「分布外扰动」可能根本不是这个系统的主要失败模式——**先把最大的失败模式排出来，再决定买什么保险**。多任务模型里，一个头的鲁棒性提升以另一个头的性能为代价，这笔交易我没有做成。

## 九、对比预训练：InfoTS 的体面退场

还有一条并行线：用对比学习在无标签数据上预训练时序表示，再微调排序头。脉络是 InfoNCE 出自 CPC（van den Oord et al., 2018），时序领域的代表工作有 TS2Vec（AAAI 2022）、TS-TCC（IJCAI 2021）、InfoTS（信息感知增强，ICLR 2024）。

这条线在 `phase5_status.md` 里被正式 CLOSED——不是因为爆了，而是因为预训练收益不足以覆盖工程复杂度，在预算盘点时被砍掉。事后看这几乎是注定的：「无监督预训练 + 下游微调」在 CV/NLP 的成功有个隐含前提——预训练表示和下游任务同构。图像里「同一物体的两个视角」语义稳定；而 K 线的「相似形态」与未来收益的相关性要弱得多。**预训练目标与下游目标的错位，是这条线收益有限的根本原因**。记录在案，防止后人重复造轮子——这是全项目唯一一个「主动放弃」而非「被打败」的实验。

## 十、不确定性也要校准：共形预测的实践

排序分数之外，模型还输出波动率和分位数区间。区间预测有个致命问题：**模型说自己 90% 置信，实际覆盖了多少？** 不自欺的办法是共形预测（Conformal Prediction）。

核心思想朴素得可爱：Split Conformal 只用校准集上的残差分布，就能给出带有限样本边际覆盖保证的区间——对数据分布几乎不做参数假设，只需要可交换性。CQR（Conformalized Quantile Regression，Romano et al., NeurIPS 2019）把它嫁接到分位数回归上：模型先学条件分位数，共形层再在校准集上学一个修正量，把「模型自以为的区间」修正成「实际达标的区间」。我用的变体是 Rolling CQR（`calibration/conformal.py`）：校准集随时间滚动以适应分布漂移——代价是严格可交换性被破坏，覆盖保证从定理退化成经验性质，这是工程上必须承认的妥协。

OOS 实测覆盖率（`phase3c_status.md`）：三个被校准对象分别为 **0.7840、0.8998、0.8397**。如果按常见的 0.80 / 0.90 名义目标衡量：一个贴近目标、一个明显欠覆盖。欠覆盖的含义很直白——尾部风险被系统性低估。这不是「以后再调」的小问题：所有依赖区间的下游决策（仓位、止损、置信闸门）都会因此偏激进。

顺带一个更扎心的数字：方向头的 OOS Brier 分数是 **0.2274**——作为参照，抛硬币基线是 0.25。也就是说方向判别力只比随机好一点点。这个数字和模拟盘的一个怪现象互为因果，第十二节讲。

## 十一、制品契约：ONNX + Manifest + 黄金输入输出

模型要进 C++ 引擎，不能靠「把 PyTorch 模型拷过去」。制品契约（`docs/champion_artifact_registration.md`）：

- **ONNX**：opset 18，导出脚本 `python/qbt_ml/export/onnx_export.py`；
- **manifest.json**：记录 `model_sha256`、`feature_schema_sha256`、`label_spec_sha256`、`ranking_score_spec_sha256`、calendar/universe id、data cutoff——**特征、标签、打分口径任何一个变了，模型哈希就对不上**，引擎拒载；
- **黄金 I/O**：一组固定输入 → 固定输出，C++ 推理结果必须逐位对齐。

这套东西在业界有名字：**模型治理（Model Governance）**。金融机构的模型风险管理（美联储 SR 11-7 指引的精神）要求任何进入决策链的模型可识别、可复现、可审计。manifest 里的四个 SHA-256 就是对「这个分数到底由哪套代码、哪套特征口径、哪个时间点的数据产生」的完整回答。黄金 I/O 则是 snapshot testing 思想在 ML 上的应用：环境变了（ONNX Runtime 升级、arm64 与 x86 的浮点差异），输出必须逐位一致，否则拒载。

这里有一个真实的 bug 值得讲：导出后我发现 ONNX 推理在某些输入下出现 NaN——原因是序列尾部 padding 位置的特征在标准化后产生 `0 × inf`。修复是 `SafeExportWrapper`：`torch.where(isfinite(x), x, 0)`，在导出层把非有限值显式归零，而不是指望运行时兜底。修复后 C++（ONNX Runtime 1.19.2 arm64）与 PyTorch 在 1587 个截面、零错误率下完全一致。

第一节埋的伏笔在这里兑现：标准化参数（mean/scale/protected）作为 buffer 进模型，随 ONNX 一起导出——**推理时的标准化就是训练时的标准化，没有第二套口径**。冠军制品 `champion-temporal-transformer-v1`（legacy 损失、fold-3、safe 导出）的冻结信息：训练窗口 2021-04-19 → 2023-05-17，data cutoff 2023-05-17T07:00:00Z，冻结时点 OOS NDCG@20 = 0.6328、RankIC = 0.0300，制品 SHA-256 以 `0ef338fe` 开头。

## 十二、模拟盘：17 个月，以及三个还没解决的诚实问题

冠军模型在 2025-04 到 2026-09 的模拟盘上跑了 17 个月：

- 总收益 **+15.80%（毛）**，扣显式成本后 **+14.45%**；
- 按 14bp 滑点再扣一遍，**+12.12%**；
- 换手率约 4.4 倍/年——收益主要来自 alpha 而非频繁交易。

**成本常识**（公开市场规则，非本系统私有参数）：A 股显性成本大致三部分——佣金（市场化定价，常见万 1.5–万 3，双边收取）、印花税（2023 年 8 月 28 日起卖出单边 0.05%）、过户费（可忽略量级）。隐性成本是滑点/冲击成本，取决于资金量与流动性，我用 14bp 做压力口径。算术很残酷：**年换手 4.4 倍的策略，每 1bp 单边成本约吃掉年化 0.04% 收益**；如果是年换手 50 倍的策略，光是成本就能磨掉大部分截面 alpha。这就是为什么 turnover 必须进 gate、不能只盯 IC。

模拟盘暴露了三个我没有答案的问题，如实记录：

**1. 水平线错配**。训练标签是持有 5 根 K 线，但 OOS 诊断显示 RankIC 在 20 根水平上最高（0.0817，t=9.18），5 根上只有 0.0599（t=6.43）。模型学的其实是「更慢的 alpha」，而交易系统按 5 根持有（实际中位持有 6 天）。用 20 根水平重训是一条明路，但样本有效数量会进一步缩水，我还没想清楚怎么权衡。

**2. 候选池变薄**。Python 研究层每个截面有约 108 个有效窗口，但 C++ 引擎里同一时刻只有 9-16 只股票给出有效预测，差了一个数量级。嫌疑在 C++ 侧的特征管线 `bar_v1_feature_pipeline.cpp`：`valid_` 的判定（finite ∧ tradable）可能与研究层语义不一致，导致候选池被过度裁剪。这条线还在排查，没定性。

**3. 置信度闸门把订单全挡了**。模拟盘配置了 `minimum_confidence = 0.55`，结果整整 17 个月 **0 笔成交**——`champion-artifact-backtest/backtest_summary.json` 里 orders=0。把第十节的 Brier 分数放在一起看就通了：方向头只比随机好一点，意味着绝大多数日子的概率输出挤在 0.5 附近，0.55 的阈值自然几乎无票通过。**闸门没坏，是头太弱**。修复路径要么是重新校准（Platt scaling / isotonic regression），要么干脆把闸门信号从 direction 头换成排序分数的截面分位数。这是当前最优先的待办。

## 十三、这一趟下来，我学到了什么

写到最后，把能沉淀的沉淀下来：

1. **预注册实验设计是防自欺的唯一武器**。这一整轮消融里，几乎每个「听起来更高级」的方法都在局部指标上给过我希望（Kendall 的 NDCG 几乎没掉、PCGrad 的 RankIC 提升、对抗训练的方向鲁棒性），如果实验不是提前写死 gate、不是 fail-closed，我大概率会挑一个「局部好看」的方法上生产，然后在真实盘里付学费。

2. **负结果要留证据链**。ListMLE 输给了 Pearson、LambdaLoss RankIC 转负、Kendall 权重翻车、PCGrad/GradNorm 组合退化、三种对抗训练全部未过门——每一个都被完整记录（实验配置、种子、fold 明细、postmortem），并带 SHA-256 契约哈希。这些不是「失败」，是防止后人重复烧钱的公共品。

3. **模型门禁在经济学门禁之前，且两者独立**。整个 2026 年，`promotion_eligible = false` 始终成立——模型可以因为 alpha 不够被拒，也可以因为风险维度退化（如 Kendall 的 spread 腰斩）被拒，任何一个没过都不上生产。模拟盘的 0 成交就是这条纪律的直接后果：**宁可空仓 17 个月，也不把未达标的模型放出去**。

4. **小模型 + 干净的实验纪律，比大模型 + 混乱的实验流程产出更多可用的知识**。d_model=64 的模型，算力成本可以忽略不计，换来的是每一轮实验都能跑几十个 fold、每一条结论都能重复验证。研究的瓶颈从来不在算力，在诚实。

5. 最后一条，也是最有争议的一条：**在这个数据体量下，朴素基线没有被超越，可能不是因为我不够努力，而是因为问题本身的信息量就那么多**。A 股截面、5 根持有、约 120 只股票、17 个月模拟盘——也许这个设定下能榨出来的 alpha 就这么多。把这一点写下来，比假装我找到了银弹，对下一个做这件事的人更有用。
